# Cue

Cue is a hackathon MVP (Immerse the Bay, 2026-11-14). A person signals interest
with a backward swipe on the temple touch strip of Mentra Live smart glasses.
If the other person in the same demo session signals interest too, the web app
creates a match. The match card shows the other person's approved profile, the
encounter time, and a coarse venue label. Matched people can text each other
inside the app. An optional "Find common ground" card, generated by Claude, shows
things supported by both approved profiles and one optional opening question that
a person can drop into the message box with "Use this opener".

This is a hackathon prototype, not a production service.

## How it works

1. Each person creates a profile and chooses, field by field, what a match can
   see. A profile can include age, gender, city, what they are looking for,
   work or school, education, MBTI, personality cards and, optionally, ethnicity
   and drinking, smoking and drugs (those four, and work or school and education,
   are off by default). The server derives one of twelve characters (for example
   "The Night Owl") from the cards. External social links are not collected.
2. An organizer creates a two-person demo session and the second person joins
   it with the join code. Only these two accounts can interact.
3. Both turn on encounter mode.
4. Person A makes a backward swipe on Mentra Live glasses. The swipe is
   submitted as interest. Person B taps "Interested" in the web app, or
   (experimental, not verified on a device) double taps Meta Adventurer glasses
   paired to an iPhone: the signed-in web page receives the headset media
   command and sends it as interest (`headset_remote`).
5. If both signals arrive within 15 seconds (server receipt time), the server
   creates one match and consumes both signals. Otherwise the first signal
   expires and nothing is shared.
6. The two people can text each other in the app while the match is active.
   Unmatch or Block ends the match and deletes the conversation.
7. "Find common ground" is optional and only shown to the person who asks.
   Claude sees only the fields each person shared with AI assist on, never age,
   gender, ethnicity, drinking, smoking or drugs, and never chat messages. It
   writes one opener and sends nothing.

The one-sided interest stays invisible to the other person. See `docs/spec.md`
for the original product behavior, `docs/profiles-and-chat.md` for profiles,
the character and chat (added later, on the owner's instruction, and a departure
from the spec), and `docs/architecture.md` for the technical contract.

### Hardware status

**Mentra Live.** The real-swipe checkpoint is **met** (2026-11-14): seven real
swipes reached the live server under the wearer's account in about 0.2 to 0.3 s
and two matches completed. On that unit the swipe's gesture name was not the
built-in default, so the mini app's calibration override was needed. Hair
adjustments, the pocket test, the media-control conflict and glasses audio are
not yet recorded. See `docs/hardware-check.md`.

**Meta Adventurer.** Not verified. The web page listens for headset media
commands (double tap by default). Tests cover the server path and the page
logic only; nobody has run it on real Meta glasses or an iPhone. The signal
shows that some Bluetooth headset sent a media command, not that Meta glasses
did, and the gesture is a tap pattern, not a swipe. See
`docs/meta-glasses-check.md`.

## Run it locally

Prerequisites: Node 22 or newer, pnpm, and Docker (for the local Supabase stack).

```bash
pnpm install
pnpm stack:start    # local Supabase in Docker; writes apps/web/.env.local
pnpm dev            # http://localhost:3000
```

Other commands:

```bash
pnpm stack:reset    # re-apply migrations and seed data
pnpm stack:stop     # stop the local Supabase stack
pnpm --filter @cue/web build
```

Seeded synthetic demo accounts (password for all three: `cue-demo-123`):

- `alex@cue.demo`
- `sam@cue.demo` (Alex and Sam share some interests)
- `riley@cue.demo` (outside the demo session; use to check rejection)

All three have full synthetic profiles. Alex fills the sensitive fields and
shares none of them.

Set `ANTHROPIC_API_KEY` in `apps/web/.env.local` to enable the Claude card.
Without it, matching still works and the card shows a retry or error state.

## Environment variables

Values for the three Supabase variables are written by `pnpm stack:start`.
Put the others in `apps/web/.env.local` by hand. Never commit real values.

| Variable | Required | Where it is used | Notes |
|---|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Yes | Browser and server | Local stack URL. Written by `pnpm stack:start`. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Yes | Browser and server | Anon key. Written by `pnpm stack:start`. |
| `SUPABASE_SERVICE_ROLE_KEY` | Yes | Server only | Never sent to a browser or the glasses. Written by `pnpm stack:start`. |
| `ANTHROPIC_API_KEY` | For the Claude card | Server only | Without it the card shows a retry or error state; matching still works. |
| `ANTHROPIC_MODEL` | No | Server only | Default `claude-opus-5-5`. |
| `WINGMAN_TIMEOUT_MS` | No | Server only | Default `15000`. |
| `ANTHROPIC_BASE_URL` | No | Server only | Used by tests to point at a local fake Anthropic server. |
| `ANTHROPIC_FALLBACKS` | No | Server only | Set to `off` to disable the server-side refusal fallback parameter. |

## Tests

```bash
pnpm typecheck && pnpm lint && pnpm test   # all workspace packages
pnpm --filter @cue/web build
pnpm test:e2e                              # Playwright; needs the local stack
```

The end-to-end tests use a fake Anthropic server and never call the real API.

Live Claude check (needs a real `ANTHROPIC_API_KEY`; skipped in the normal test
run). It sends the synthetic seeded-style pair, a no-overlap pair and a profile
containing instructions to the real model and prints raw and validated output:

```bash
WINGMAN_LIVE=1 ANTHROPIC_API_KEY=sk-ant-... \
  pnpm --filter @cue/web exec vitest run src/server/ai/live.test.ts
```

The live model call has not been verified yet because no API key has been
available for it.

## Limitations

- Normally one pair of glasses: one person uses the glasses, the other the web
  app. The Meta route allows two glasses wearers but is not verified on a device.
- `headset_remote` is not proof of device: any Bluetooth headset sending a media
  command on that phone would trigger it. The Meta gesture is a tap pattern, not
  the backward swipe.
- The session is pre-scoped to two accounts by the organizer. This is not crowd
  identification, and location is not proof of who someone meant to choose.
- No identity verification.
- The venue is a manual label. There are no coordinates.
- Chat is text only, inside the app. There is no feed and there are no push
  notifications. Live updates are in-app only.
- Chat cannot stop someone typing their own contact details. Removing social
  links and not linking URLs lowers exposure; it does not enforce anything.
- There is no message reporting or moderation beyond Unmatch and Block.
- Ethnicity and substance use are sensitive. They are optional, hidden by default
  and never sent to Claude, but they are stored in the database once filled in,
  and this project has no privacy policy. Use synthetic data for demos.
- Age is self-declared and not verified. Nothing about a person is verified.
- The chat send limit is in memory and works only on a single server instance.
- The rate limit for the Claude card is in memory and works only on a single
  server instance.
- The live Claude call is not verified until an API key is supplied, and the
  fuller input (cards, character, MBTI, location and so on) has not been run
  live. Automated tests use a fake model.
- The profile, character and chat screens have not been tried on the real phones.
- The Mentra swipe was verified on one real unit (see Hardware status); the Meta
  tap route has not been run on real hardware.
- The end-to-end tests cover the server path (device-token and `headset_remote`
  events). They do not test a physical swipe or tap.
- Hackathon MVP. Not production software.
